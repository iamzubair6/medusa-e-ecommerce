# Tests #129–#137 — Round 6: campaigns, free delivery, promo visibility, phone reward, email templates, recovery v2, consent

**What was built:** campaigns now drive the storefront (banner + code); free
delivery has a real over-৳X rule; active promo codes advertise themselves in
the cart; verified phones earn a personal one-time code; email templates got
live previews + your own custom templates with bulk send; abandoned-cart
recovery gained a discount incentive + bulk send; guest leads gained filters +
CSV; a cookie-consent banner gates marketing popups.

## 1. Campaigns (#129) — /admin/campaigns

- [ ] Create a campaign: name, Status **active**, Starts = now, banner text
      "TEST RUN — 20% OFF", banner link `/products`, promo code of a REAL code
      from Discounts.
- [ ] Storefront (refresh): the top announcement bar now shows
      "TEST RUN — 20% OFF — use code …" and links to /products.
- [ ] Cart drawer: the campaign's code appears as the FIRST suggestion chip.
- [ ] **Pause** the campaign → banner returns to the normal announcement.
- [ ] Pencil icon opens an edit form prefilled; change the banner text → Save →
      toast confirms; storefront shows the new text when re-activated.
- [ ] Trash icon asks for confirmation before deleting; a toast confirms.

## 2. Free delivery (#130) — /admin/shipping + storefront

- [ ] Each delivery rate now has a **"Free over ৳ (optional)"** field. Set 2000
      on a rate → Save → toast shows "৳X, free over ৳2000".
- [ ] Cart drawer with a cheap item: a progress strip says
      "Add ৳… more for free delivery" and fills as you add items.
- [ ] Add items past ৳2,000 → strip flips to "You've unlocked free delivery";
      at checkout that rate shows **৳0**.
- [ ] Clear the field ("") → Save → checkout charges the normal rate again.
- [ ] Product form has "Free delivery badge" — tick it on one product → its
      card shows FREE DELIVERY and the PDP shows the gold badge.
      (Badge is informational; order-level free shipping = the threshold above.)

## 3. Promo visibility (#131) — storefront cart/checkout

- [ ] With at least one active coded promo, the cart drawer shows dashed chips
      like "WELCOME10 · 10% off" under the promo input.
- [ ] Clicking a chip applies the code (discount row appears); the chip
      disappears from suggestions while applied.
- [ ] Personal codes (PH-…), the Shop-the-Look bundle code and the persona code
      are NEVER suggested.

## 4. Phone reward (#132) — /admin/discounts + storefront popup

- [ ] /admin/discounts → "Phone verification reward" card: enable, 5%, save.
- [ ] Incognito: phone popup → enter number → OTP → after verifying, a reward
      step shows **your personal code PH-XXXXXX** ("already applied to your cart").
- [ ] The cart shows the code applied; complete an order → trying the code
      again on a new cart is rejected (one-time).
- [ ] Re-verifying the same phone shows the SAME code (no farming).
- [ ] Disable the reward in admin → new verifications get no code.

## 5. Email templates v2 (#136) — /admin/email-templates + /admin/customers

- [ ] Every fixed template (OTP, order emails, welcome, **Back in stock**,
      **Abandoned cart recovery**) opens with a **live inbox preview** that

- [ ] "Your templates" → New template: name, subject, heading, HTML body →
      preview renders in the brand shell → Create → appears in the list.
- [ ] Edit + delete (with confirm dialog) work; "Send test" lands in your inbox.
- [ ] /admin/customers → "Email campaign" card: pick your template, audience
      count shows, type `SEND <count>` → Send → toast reports how many sent.
- [ ] Campaigns over 300 recipients are blocked (Brevo free tier).
